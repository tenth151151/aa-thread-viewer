# spotless の対象を、ソースの場所に絞る

spotless の対象は、`**/*.kt` と `**/*.gradle.kts` のままにし、外したい場所を `targetExclude` に足していく形を保ちます。対象を `app/src/**/*.kt` のような、ソースの場所をはっきり書く形には絞りません。

## 対象を絞らない理由

対象を絞る形では、新しいソースの場所 (モジュールや `buildSrc` など) を足したときに、対象に書き足すのを忘れると、そのファイルが検査されないままになり、誰も気づきません。今の形では、新しいソースの場所は、何もしなくても対象に入ります。

今の形にも弱点があります。想定していない場所に git worktree や clone を置くと、spotless は中のファイルも対象にします。書式が崩れたファイルがあれば `./gradlew check` が落ちて気づけますが、崩れていなければ気づけません。`./gradlew spotlessApply` を実行すると、その中のファイルも書き換えます。外すには、その場所を `targetExclude` に足す必要があり、1 人の手元だけの場所でも、共有の `build.gradle.kts` を変えることになります。

worktree は `.claude/worktrees/` に置く決まりで、この場所は `targetExclude` で外しています。そのため、想定していない場所に置くことはまれです。どちらの形の失敗もまれですが、新しいソースが黙って検査から漏れるほうが、害が大きいと考えます。
