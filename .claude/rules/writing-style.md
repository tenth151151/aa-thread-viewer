# 文体のルール

リポジトリに書く日本語の文体を統一します。コード、コメント、コンソール出力、ドキュメントを書くとき、変更するときに必ず従います。

## 文体と句点

| 対象 | 文体 | 句点 |
|---|---|---|
| コンソール出力 (ログ、エラーメッセージ)、ドキュメント (README、`.md`。`CLAUDE.md` と一部のスキルは例外。下の「常体で書くドキュメント」を参照) | です・ます調 | 文末に付ける |
| コードコメント (シェル、Dockerfile、JSON などすべて) | 常体 (する・である調、体言止めも可) | 文末に付ける |
| コミットメッセージ | 既存の履歴に合わせて「〜した」調 (Dependabot は例外。下の「コミットメッセージの例外」を参照) | 付けない |

```bash
# 標準入力が端末のときだけ -t を付ける。
log "Claude Code をインストールします。"
```

### コミットメッセージの例外

Dependabot が作るコミットは、英語の既定のメッセージ (`Bump ...`) のままにします。それ以外のコミットは「〜した」調で書きます。

### 常体で書くドキュメント

次のファイルは、常体 (する・である調) で書きます。例外の一覧は、この節を正とします。

- `CLAUDE.md`
- `.claude/skills/squash-commits/SKILL.md`

理由は、既存の書き方を踏襲するためです。

ルール (`.claude/rules/`)、エージェント (`.claude/agents/`)、`tdd` と `pre-pr-check` の `SKILL.md`、`README.md` は、です・ます調で書きます。新しいスキルも、です・ます調で書きます。常体で書くときは、この節の一覧に足します。

### 句点の例外

- 見出しのコメントには付けません。`# ---` で囲んだセクション見出しのタイトル行と、後ろに説明の行 (`#   ...` や `# * ...`) が続くタイトル行の、どちらも対象です。説明の行は、通常のコメントとして句点を付けます。
- 文末が `！` `？` の文には、句点を重ねません。
- コマンド名、パス、URL、バージョンなどの値で終わる行は、句点を付けると誤読されやすいので付けません。
- 文の途中で改行したコメントは、最後の行にだけ句点を付けます。
- 括弧書きだけで 1 文になるときは、括弧の中に句点を入れます (例: `# (理由はこれである。)`)。

## 書式

- 句読点は全角の `、` `。` を使います。
- 日本語と英数字の間には、半角スペースを入れます (例: `sudo を削除します。`)。
- 丸括弧は半角の `(` `)` を使います。全角の丸括弧 (U+FF08、U+FF09) は使いません。
  - 半角の丸括弧と、日本語、英数字、インラインコードの間には、括弧の外側に半角スペースを入れます (例: `常体 (する・である調) で書きます。`)。括弧の内側にはスペースを入れません。
  - 次の場所には、スペースを入れません。
    - 句読点 (`、` `。`) の前後と、`:` の前。
    - 行頭と行末。
    - ほかの括弧類 (`「` `」` `[` `]` `(` `)` など) の隣。
  - コードの中の括弧 (関数呼び出しなど) には、この決まりを当てはめません。
  - 全角の丸括弧があるかどうかは、`bin/check-fullwidth-parens.sh` で調べます。CI と Claude Code のフック (`.claude/settings.json`) で自動で動きます。スペースの付け方は検査しません。
  - フックは Write、Edit、MultiEdit、NotebookEdit のあとに動き、編集したファイルだけを検査します。ファイルは、それが属する git のリポジトリ (別の git worktree を含む) の中で検査します。git のリポジトリに属さないファイルは検査しません。編集したファイルのパスを取り出せないとき (`jq` がないときなど) は、リポジトリ全体を検査します。Bash のコマンドで書き換えたときも、フックでは見つかりません。そのときも、CI で見つかります。
  - アプリの画面に出す文字列 (`app/src/*/res/`) と、テストのデータ (`app/src/*/resources/`) は、AA を含むことがあるので、検査の対象外です。AA を含む文字列は、Kotlin のコードに直接書かず、これらのファイルに置きます。画面の文章の書き方は、別に決めます。
- 省略記号は `…` を使うか、使わずに書きます (`...` は使いません)。
- 複数の文を書くときも、各文を句点で区切ります。

## 口調の設定をファイルに持ち込まない

チャットでの返答に使う口調やキャラクターの設定 (語尾など) を、コード、コメント、コンソール出力、ドキュメント、コミットメッセージに書いてはいけません。ファイルに書く文章は、上の表のとおりに書きます。
