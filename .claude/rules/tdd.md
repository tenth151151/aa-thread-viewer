# TDD のルール

本プロジェクトは、テスト駆動開発 (TDD) で進めます。コードを追加、変更、修正するときは、必ず従います。

## サイクル

1. **赤**: 実装より先に、期待する振る舞いを表す失敗するテストを書きます。
2. テストを実行し、意図した理由で失敗することを確認します。テストが最初から通る場合や、期待と違う理由で失敗する場合は、テストを直します。
3. **緑**: テストを通すための最小限の実装を書きます。先回りして機能を足しません。
4. テストを実行し、すべて通ることを確認します。
5. **リファクタリング**: テストが通ったまま、重複や分かりにくさを整えます。整えるたびにテストを実行します。

## 運用

- 機能追加も、バグ修正も、同じ流れで進めます。バグ修正では、まず不具合を再現するテストを書きます。
- 1 回のサイクルで扱う振る舞いは、1 つにします。複数あるときは、サイクルを分けます。
- テストを通すために、テスト自体を弱めたり、削除したり、スキップしたりしません。テストが誤っているときは、理由を説明したうえで直します。
- 警告をエラーにする設定 (Kotlin のコンパイラと Android Lint) は、緩めません。警告を抑える書き方も、設定を緩めるのと同じに扱い、使いません。警告は、コードを直して消します。
  - 抑える書き方の例は、Kotlin の `@Suppress(...)`、`@file:Suppress(...)`、`freeCompilerArgs`、lint の `@SuppressLint`、`tools:ignore`、`lint.xml`、baseline、コードの警告を消すための `disable` への追加です。
  - `app/build.gradle.kts` に既にある lint の `disable` は、外部の状況で結果が変わる検査 (依存や AGP の版の検査) を、Dependabot に任せるために無効にしたものです。コードの警告を消す目的ではないので、この決まりの対象外です。ほかの検査を `disable` に足すときも、相談します。
  - 抑える必要があると思ったときは、作業を止めて、ユーザーに相談します (worker は supervisor に伝えます)。
  - この決まりは、テストを書かない変更 (Dependabot の PR で落ちた CI を直すときなど) や、ドキュメント、設定の変更にも当てはまります。
- カバレッジの基準値 (`app/build.gradle.kts` の `kover` の `minBound`) は、下げません。測る対象からの除外 (`annotatedBy`、`inheritedFrom`、`classes` など) も、`check` を通すために足しません。カバレッジが足りないときは、テストを足します。
  - `app/build.gradle.kts` に既にある除外 (`@Composable` の関数、Activity と Application とその親のクラス、`*ComposableSingletons*`) は、計装テストを使わないので測れないものを外す前提です。この決まりの対象外です。
  - Activity や Application の親をライブラリのクラス (例: `AppCompatActivity`) に変えたときに、そのクラスを `inheritedFrom` に足すのは、今の方針 (Activity と Application を外す) を保つための追加なので、相談せずに足してかまいません。Kover は、ライブラリのクラスの継承をたどれないためです。
  - それ以外の除外を足す必要があるときや、基準値を変えたいときは、作業を止めて、ユーザーに相談します (worker は supervisor に伝えます)。
  - この決まりは、テストを書かない変更にも当てはまります。
- 実行して確認していないテストや実装は、確認済みとして報告しません。実行できなかったときは、そう明記します。
- 作業の分担は次のとおりです。
  - `worker` が、赤、緑、リファクタリングを一貫して担当します。
  - `reviewer` は、テストが先に書かれているか、テストが振る舞いを正しく表しているかを確認します。

## 例外

次のように、テストを書く意味が薄い変更は、先にテストを書かなくてかまいません。例外にしたときは、作業の報告にその旨と理由を書きます。

- ドキュメント、ルール、スキルの変更。
- 設定ファイル、Dockerfile、devcontainer など、環境構築まわりの変更。
- 実行して確かめるだけの使い捨てのスクリプト。

例外にしても、警告を抑えない決まりと、カバレッジの基準値と除外を緩めない決まり (「運用」の節) は外れません。
