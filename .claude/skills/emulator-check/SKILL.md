# エミュレータでアプリを確かめる

起動済みのエミュレータに debug ビルドを入れ、dat を置いて、画面を操作して確かめます。JVM の単体テストでは確かめられないもの (Activity の仕組み、ファイルの選択画面、文字コード、プロセスが作り直されたあとの復元) が対象です。

## 守ること

- エミュレータの起動、停止、設定の変更はしません。つながらないときは、手順 1 のとおり止めて伝えます。
- 元に戻せない操作 (アプリのアンインストール、端末のデータの削除やリセットなど) は、依頼がなければしません。ただし、手順 7 で、自分が置いたファイル (控えたパス) を消すことは除きます。要ると思ったときは、止めて伝えます (`.claude/agents/worker.md` の決まりと同じです)。
- 途中で止めるとき (手順 1、2、5、6 などでユーザーに伝えて止めるとき) も、それまでに端末に置いたファイルを、手順 7 のとおり消してから報告します。置いたものがなければ、消すものはありません。
- 確認の証拠 (スクリーンショット、`uiautomator dump` の出力、端末に置く dat) は、メインの作業ツリーの `.tmp/<ブランチ名>/` に置きます。どの worktree で作業しても、同じ場所です。ユーザーが見るためのファイルで、`.gitignore` されています。置き場所の決まりは `CLAUDE.md` の「開発環境」にあります。下書きの UTF-8 の dat などの途中のファイルは、スクラッチパッドに置きます。
- 出力先は、相対パスではなく、メインの作業ツリーから作った絶対パスで書きます。
  - メインの作業ツリーは、`git rev-parse --path-format=absolute --git-common-dir` が返すパスの 1 つ上のディレクトリです (`/post-merge-cleanup` と同じです)。
  - 今いる作業ツリーの `--show-toplevel` から作ると、手で `git worktree add` した worktree では、証拠が worktree の中に分かれ、後片付けの一覧に出ません。
  - 相対パスだと、カレントディレクトリによっては別の場所にファイルができます。
  - ブランチ名は、今いる作業ツリーのものです。
  - Bash ツールではシェルの変数が呼び出しをまたいで残らないので、`<証拠のディレクトリ>` を使う Bash の呼び出しごとに、次のコマンドをその呼び出しの中で設定し直し、`<証拠のディレクトリ>` は `"$evidence"` として使います。
  - `git branch --show-current` が空 (HEAD が切り離されている) のときと、ブランチ名が `retro-log` か `retro-log/` で始まるときは、コマンドが止まるので、ファイルを置かず、止めて伝えます (`.tmp/retro-log/` はふりかえりの記録の場所です)。
- 証拠のファイルは、上書きしません。撮り直すたびに前の証拠が消えないよう、書く前に、同じ名前のファイルがないかを確かめ、あれば `-2`、`-3` を付けた名前にします。次のコマンドの関数 `evidence_path` が、空いているパスを返します。呼び出しごとに設定し直すコマンドに含めます。
- ファイル名の幹には、順番と何の画面かが分かる区別を付けます (例: `screen-01-home`、`window_dump-02-thread`)。
- 書いたパスは、次の呼び出しで使うので、文章で控えます (シェルの変数は、呼び出しをまたいで残らないためです)。

  ```bash
  branch="$(git branch --show-current)"
  [ -n "$branch" ] || { echo "HEAD が切り離されているので、証拠のディレクトリを決められません。" >&2; exit 1; }
  case "$branch" in
    retro-log | retro-log/*) echo "ブランチ名が retro-log か retro-log/ で始まるので、証拠のディレクトリを決められません。" >&2; exit 1 ;;
  esac
  common="$(git rev-parse --path-format=absolute --git-common-dir)" || { echo "メインの作業ツリーを調べられないので、証拠のディレクトリを決められません。" >&2; exit 1; }
  evidence="$(dirname "$common")/.tmp/$branch"
  mkdir -p "$evidence"
  # 呼ぶ前に、変数 stem (名前の幹) と ext (拡張子) を設定する。
  # 同じ名前のファイルがあれば、-2、-3 を付けた空きのパスを返す。
  # 位置の引数は使わない (理由は下の説明を見る)。
  evidence_path() {
    local n=1 p="$evidence/$stem.$ext"
    while [ -e "$p" ]; do n=$((n + 1)); p="$evidence/$stem-$n.$ext"; done
    printf '%s\n' "$p"
  }
  ```

  - `evidence_path` は、変数 `stem` と `ext` を読みます (例: `stem=sample ext=dat; evidence_path`)。位置の引数を使わないのは、スキルを引数つきで呼んだときに、本文のドルの記号に数字や引数の全体を表す語が続く書き方が、渡した引数の語に置き換わるためです。公式の Skills のページ (https://code.claude.com/docs/en/skills) の「Available string substitutions」の節には、引数の置き換えの書き方が載っています。コードブロックの中でも置き換わるとは、そのページに直接は書かれていません。このスキルを引数つきで呼んだとき、コードブロックの中の書き方が置き換わって表示されたのを観察しました (Claude Code 2.1.330)。コードを足すときも、シェルの位置の引数や、awk のフィールドの指定のように、ドルの記号に数字が続く書き方を、スキルの本文に書きません。

## 1. つながるかを確かめる

まず、`adb` があるかと、`ADB_SERVER_SOCKET` を確かめます。

```bash
command -v adb
echo "ADB_SERVER_SOCKET=${ADB_SERVER_SOCKET:-}"
```

- `adb` がないときは、設定を変えずに止め、つながらなかったと伝えます。つなぎ方は `README.md` を案内します。`ADB_SERVER_SOCKET` などの環境や、`.devcontainer/` の設定は触りません。
- `ADB_SERVER_SOCKET` が空のときは、`adb` を実行せず、設定を変えずに止め、つながらなかったと伝えます。`ADB_SERVER_SOCKET` などの環境や、`.devcontainer/` の設定は触りません。空のまま `adb` を実行すると、ホストの adb server を使わずに、コンテナの中で adb の daemon が起動するためです。つなぎ方は、`README.md` の `.devcontainer/.env` の手順を案内します。

`adb` があり、`ADB_SERVER_SOCKET` が空でないときだけ、次を実行します。

```bash
adb devices
```

- `adb devices` の一覧に `device` の行が 1 つもないときは、設定を変えずに止め、つながらなかったと伝えます。`ADB_SERVER_SOCKET` などの環境や、`.devcontainer/` の設定は触りません。つなぎ方は `README.md` を案内します。
  - ホストでエミュレータを起動し直してもらうときは、ホストの Windows で `bin\windows\setup-emulator.bat` を実行するよう伝えます。このバッチが呼ぶ `setup-emulator.ps1` も含め、2 つのファイルは、`bin/windows/` を管理していないブランチに切り替えると、作業ツリーから消えます。その 2 つのファイルにコミットしていない変更があるときは、git が切り替えを断ります。ファイルが見つからないときは、`main` など、ファイルがあるブランチに切り替えてから実行するよう伝えます。
    - ブランチを切り替えるのは、ユーザーか、supervisor の指示を受けた helper です。helper が切り替えるのは、ユーザーの確認を取ってからです。このスキルを使うエージェントは、自分では切り替えません。
    - 切り替えたときは、手順 2 に進む前に、`git branch --show-current` で、確かめるブランチに戻ったことを確かめます。戻っていないまま進むと、別のブランチのコードをビルドして入れ、確かめるブランチの結果として報告してしまうためです。戻っていないときは、先に進まずに止めて伝えます。
- 一覧に `offline` や `unauthorized` の行があるときも、同じように止めて伝えます。
- 端末が複数あるときは、`-s <シリアル>` を以降のすべての `adb` に付けます。

確かめた環境として、`adb version` と、エミュレータの Android の版 (`adb shell getprop ro.build.version.release`) を控え、報告に書きます。つながらなかったときは、つながらなかったと報告し、版は書かなくてかまいません。

## 2. ビルドして入れる

パッケージ名は、`app/build.gradle.kts` の `applicationId` で確かめます (以降 `<パッケージ>` と書きます)。

```bash
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

- `Success` が出ることを確かめます。
- `INSTALL_FAILED_UPDATE_INCOMPATIBLE` (署名の不一致) で失敗したときは、**アンインストールせずに止めて伝えます**。アンインストールすると、端末のアプリのデータが消えるためです。原因でよくあるのは、debug の署名鍵 (`~/.android/debug.keystore`) が、端末に入っているアプリを入れたときと違うことです。debug の署名鍵は、`~/.android/debug.keystore` がない状態で debug をビルドする (`./gradlew :app:assembleDebug`) と、そこに作られます。`~/.android` は、コンテナを作り直しても鍵が残るように、名前付きボリュームにしています。ボリュームを消すと、鍵も消えて、次のビルドで新しい鍵が作られます。別のフォルダでコンテナを開いたときや、ホストの Android Studio で入れたアプリは、鍵が違うことがあります。アンインストールするかは、ユーザーが決めます。
- 入った版は、`adb shell dumpsys package <パッケージ> | grep versionName` で確かめられます。

## 3. dat を作る

dat は `windows-31j` (CP932) の文字コードで、1 行が 1 件のレスです。形は次のとおりです。

```text
名前<>メール<>日付と ID<>本文<>タイトル
```

- 5 番目のタイトルは、1 行目にだけ書きます。2 行目以降は、5 番目を空にします (`名前<>メール<>日付と ID<>本文<>`)。
- 本文の改行は `<br>` で書きます。
- 拡張文字の確認用に、本文に `①` (CP932 で `87 40`) と `髙` (CP932 で `fb fc`) を入れます。

手順は次のとおりです。

1. スクラッチパッドに、UTF-8 の dat を Write ツールで作ります。
2. CP932 に変換します。変換後の dat は、端末に置く確かめの dat なので、`<証拠のディレクトリ>` に出します。出力先は `evidence_path` で決め (例: `sample.dat`。あれば `sample-2.dat`)、使ったパスを控えます。以降の `<証拠の dat>` は、控えたパスです。

   ```bash
   stem=sample ext=dat
   dat="$(evidence_path)"
   iconv -f UTF-8 -t CP932 <スクラッチパッド>/sample-utf8.dat > "$dat"
   echo "$dat"
   ```

3. 拡張文字のバイト列を確かめます。変換前のファイルの `①` と `髙` が、変換後に `87 40` と `fb fc` になっていれば、正しく変換できています。

   ```bash
   printf '①髙' | iconv -f UTF-8 -t CP932 | od -An -t x1
   for b in '87 40' 'fb fc'; do
     od -An -v -t x1 <証拠の dat> | tr '\n' ' ' | tr -s ' ' | grep -q " $b " && echo "$b あり" || echo "$b なし"
   done
   ```

   上のコードブロックの 1 つ目のコマンド (`iconv` と `od`) は `87 40 fb fc` を出します。`od` は 16 バイトごとに折り返すので、ファイル全体を 1 行につなげてから探します。2 つ目のコマンド (`for` の繰り返し) は、2 つのバイト列のどちらもが `あり` になれば正しく変換できています。

   `iconv` が `cannot convert` で失敗したときは、変換できない文字が入っています。その文字を dat から外します。

## 4. 端末に置く

端末に置く名前は、毎回ちがう名前にします (日時を入れます)。そのうえで、置く前に、同じパスにファイルがないかを確かめ、ないとはっきり分かったときだけ進みます。置いたパスは、手順 7 で消すために控えます。

`adb shell` の終了コードでは、「ファイルがない」と「端末につながっていない」や「`adb shell` がほかの理由で失敗した」を区別できません。そのため、端末の側で `exists` か `missing` を出させ、その文字列を受け取ります。`missing` と出たときだけ進み、それ以外 (`exists`、空、エラー) は止めます。`adb shell` の出力の末尾に `\r` が付くことがあるので、外してから比べます。先に `adb get-state` で、出力が `device` であることも確かめます。

```bash
[ "$(adb get-state 2>/dev/null)" = device ] || { echo "端末につながっていません。" >&2; exit 1; }
remote="/sdcard/Download/aatv-check-$(date +%Y%m%d-%H%M%S).dat"
r="$(adb shell "[ -e '$remote' ] && echo exists || echo missing")"
[ "${r%$'\r'}" = missing ] || { echo "端末に $remote があるか、あるかどうかを確かめられなかったので、先に進みません。" >&2; exit 1; }
echo "$remote"
adb push <証拠の dat> "$remote"
adb shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d "file://$remote"
```

- 端末に置く名前は、証拠のディレクトリの側の名前 (手順 3 の `sample.dat` など) とは別です。確かめで止めたときは、何も置かずに、ユーザーに伝えます。
- 名前は秒単位なので、同じ秒のうちにこの手順をやり直すと、確かめで止まります。止まったときは、1 秒以上待ってから、名前を決め直します。
- 次の呼び出しで使うので、`echo` で出した `$remote` のパスを文章で控えます (シェルの変数は呼び出しをまたいで残らないためです)。控えるのは、確かめを通って `push` を実行したときです。`push` が途中で失敗したときも、ファイルが一部できていることがあるので、成否にかかわらず控えて、手順 7 の消す対象に入れます。確かめで止めたとき (ファイルがもうあったとき、確かめられなかったとき) は、置いていないので、控えません。
- 複数の端末があるときは、`adb get-state`、`adb shell`、`adb push` のすべてに `-s <シリアル>` を付けます。
- コードブロックの最後の行のスキャンのブロードキャストは、必須ではありません。Android 17 のエミュレータでは、送らなくても、ファイルの選択画面にファイルが出ました。まず、ブロードキャストの行を除いた `push` までを実行し、選択画面にファイルが出なかったときにブロードキャストを送ります。あとから送る呼び出しではシェルの変数 `remote` が残っていないので、行をそのまま写さず、控えた dat のパスを書き込んで送ります (例: `adb shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file://<控えた dat のパス>`)。
- 新しい Android では、このブロードキャストが非推奨のことがあり、効かないときがあります。送っても出ないときは、選択画面を開き直してから、ユーザーに伝えます。
- 選択画面にファイルが出たかどうか (ブロードキャストを送ったかどうかも) を、エミュレータの版と一緒に報告に書きます。

## 5. 画面を操作して確かめる

画面の部品は、`uiautomator dump` で位置を調べて、`input tap` で押します。

dump は端末にファイルを書くので、最初の dump の前に、次のコードブロックを実行します。手順 4 と同じ形で、手で書き換えずにそのまま実行できます。

```bash
[ "$(adb get-state 2>/dev/null)" = device ] || { echo "端末につながっていません。" >&2; exit 1; }
remote_dump="/sdcard/aatv-window-dump-$(date +%Y%m%d-%H%M%S).xml"
r="$(adb shell "[ -e '$remote_dump' ] && echo exists || echo missing")"
[ "${r%$'\r'}" = missing ] || { echo "端末に $remote_dump があるか、あるかどうかを確かめられなかったので、先に進みません。" >&2; exit 1; }
echo "$remote_dump"
```

- 決めたパスを、以降のすべての dump の出力先にし (手順 6 の dump も同じです)、手順 7 で消すために控えます。控えるのは、最初の dump を実行したときです。dump が途中で失敗したときも、成否にかかわらず控えます。確かめで止めたとき (ファイルがもうあったとき、確かめられなかったとき) は、控えません。同じ秒のうちにやり直して止まったときの扱いも、手順 4 と同じです。

控えた `$remote_dump` のパスを使って、dump を取ります。次のコードの `<端末の dump>` は、控えたパスです。

```bash
adb shell uiautomator dump <端末の dump>
stem=window_dump-01-home ext=xml   # 証拠のファイルは、evidence_path で上書きを避ける。
dump="$(evidence_path)"
adb exec-out cat <端末の dump> > "$dump"
echo "$dump"
adb shell input tap <x> <y>
stem=screen-01-home ext=png
shot="$(evidence_path)"
adb exec-out screencap -p > "$shot"
echo "$shot"
```

- 端末の dump の出力先 (`$remote_dump`) は、dump のたびに同じパスへ上書きしてかまいません (自分が決めた名前で、手順 7 で消します)。上書きを避けるのは、`<証拠のディレクトリ>` の側のファイルです。dump と画面ごとに、順番と画面が分かる名前 (`window_dump-02-thread`、`screen-02-thread` など) を付けます。
- 押す場所は、控えた dump のファイル (`<証拠の dump>`) の該当する `node` の `bounds="[左,上][右,下]"` から、中心の座標を計算します。画面の表示が変わるたびに、dump を取り直します。
- 座標は、dump から次のように探せます (ボタンの文字が `dat を開く` の例)。`bounds` の真ん中を `input tap` に渡します。

  ```bash
  grep -o 'text="dat を開く"[^>]*bounds="\[[0-9,]*\]\[[0-9,]*\]"' <証拠の dump>
  # 例: bounds="[40,300][280,380]" なら、中心は x=(40+280)/2=160、y=(300+380)/2=340
  adb shell input tap 160 340
  ```

- 1 画面に収まらない長いスレッドは、`input swipe` でスクロールします。画面の大きさは `adb shell wm size` で確かめ、画面の幅の真ん中で、下から上へ動かします (指を上へ動かすと、内容が下へ進みます)。最後は、スクロールしても dump の内容が変わらなくなったことで分かります。

  ```bash
  adb shell wm size   # 例: Physical size: 320x640
  # x=160 で、y=500 から y=150 へ、300 ミリ秒かけて動かす。
  adb shell input swipe 160 500 160 150 300
  ```
- スクリーンショットは Read ツールで見られます。ファイル名には、何の画面かが分かる名前を付けます。
- 文字は、スクリーンショットの見た目と、dump の `text` の両方で確かめます。dump の文字は、`①` や `髙` が化けていないかの確認にも使えます。
- ファイルの選択画面は、アプリの Activity ではなくシステムの画面です。dump の対象は同じですが、部品の名前は Android の版で違います。

### システムバーの分の余白を確かめるとき

最後の項目がナビゲーションバーに重ならないかを確かめるときは、先に、ナビゲーションバーの inset があるかを見ます。

```bash
adb shell dumpsys window | grep -n 'type=navigationBars'
```

- ジェスチャーのナビゲーションでは、`navigationBars` の inset が出ないか、0 のことがあり、重なりを確かめられないことがあります (方式は `adb shell settings get secure navigation_mode` で分かります。2 がジェスチャーです)。そのときは、確かめられなかったと報告します。エミュレータの設定 (ナビゲーションの方式) は変えません。
- 下端を確かめるには、1 画面に収まらない長い dat が要ります。手順 3 の形で、レスを十分な数まで増やして作り、上の `input swipe` で最後までスクロールします。

## 6. プロセスが作り直されたあとに戻るかを確かめる

画面の状態 (`rememberSaveable` や ViewModel の状態) が、プロセスが殺されたあとに戻るかを確かめます。

1. アプリで確かめたい画面 (例: dat を読んだスレッドの画面) を開きます。
2. ホームボタンで裏に回します。

   ```bash
   adb shell input keyevent KEYCODE_HOME
   ```

3. 5 秒待ちます。すぐに `am kill` すると、プロセスが残ることがあります。
4. プロセスを殺し、消えたことを確かめます。

   ```bash
   adb shell am kill <パッケージ>
   adb shell pidof <パッケージ>
   ```

   `pidof` が何も出さなければ、消えています。出たときは、3 から繰り返します。
5. ランチャーのアイコンからではなく、最近使ったアプリから戻します。ランチャーから起動すると、新しい起動になり、保存した状態を使わないためです。

   ```bash
   adb shell input keyevent KEYCODE_APP_SWITCH
   ```

   最近使ったアプリの一覧が出たら、`uiautomator dump` (出力先は手順 5 で決めて控えたパスです) で、アプリのカード (`snapshot` を含む node) の `bounds` を探し、その真ん中を `input tap` で押すと、アプリに戻ります。
6. 3 秒待ってから、戻した画面を `uiautomator dump` の `text` で確かめます。

戻したあとのスクリーンショットは、黒一色になることがあり、Android 17 のエミュレータ (手順 8 の確かめた環境) で試したときは 2 回とも、5 秒空けても黒一色でした。戻したあとは、スクリーンショットではなく `uiautomator dump` の `text` で内容を確かめ、見た目は確かめていないと報告します。

## 7. 置いたファイルを消す

確かめ終わったとき、または途中で止めるときは、確かめるために端末に置いたファイル (`/sdcard/Download/` に置いた dat、`uiautomator dump` の出力先など) を消します。

- 置くたびに、置いたパスを控えておきます。
- 消すのは、控えたパスだけです。1 つずつ `adb shell rm <パス>` で消します。ワイルドカードと `-r` は使いません。

  ```bash
  adb shell rm <控えた dat のパス>
  adb shell rm <控えた dump のパス>
  ```

- 自分で置いていないファイルは消しません。手順 4 の dat と手順 5 の dump の出力先は、どちらも、毎回ちがう名前 (日時入り) にし、置く前に同じパスのファイルがないことを確かめ、ないとはっきり分かったときだけ進むので、控えたパスは自分が置いたものだけです。確かめで止めたパス (ファイルがもうあったとき、確かめられなかったとき) は、控えません (置いていないので、消しません)。`push` や dump を実行したあとは、途中で失敗しても控えて、消す対象に入れます。
- 入れた debug のアプリは、消さずに残します。アンインストールは、守ることのとおり、依頼がなければしません。
- 手順 8 の報告に、消したファイルと、消さずに残したファイル (入れた debug のアプリなど) を書きます。

## 8. 報告する

- 確かめた版: `adb version` と、Android の版。つながらなかったときは、つながらなかったこと。このスキルの手順を確かめた版は、adb 37.0.1 と Android 17 のエミュレータ (画面は 320x640、密度 160、ジェスチャーのナビゲーション) です。手順 4 の存在の確かめは、adb 37.0.1 と Android 17 のエミュレータで、存在するパス (`/sdcard/Download`) が `exists`、存在しないパスが `missing` を出すことを確かめました (出力の末尾に `\r` は付きませんでした)。
- 入れた APK と、確かめたパッケージ。
- 確かめた操作と、見たもの (スクリーンショットの場所、dump の `text`)。
- 確かめていないこと (戻したあとの見た目、システムバーの分の余白、スキャンのブロードキャストの効き目など)。
- 端末に置いたファイルのうち、消したものと、消さずに残したもの (あれば)。消し方は、前の「7. 置いたファイルを消す」のとおりです。
- 証拠を置いた `.tmp/<ブランチ名>/` の絶対パス (`<証拠のディレクトリ>` の中身) と、置いたファイルの名前。ユーザーが見るためのファイルです。
